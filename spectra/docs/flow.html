Spectra

How a revision is built, and the experiments that run on it. Spectra measures how frontier models write: their accents. It does not score answer quality. Every model gets the same prompts with no system prompt, through the provider layer it shares with PeerRank. Paid experiments run only after a pre-registration is committed.

Config

spectra/config.yaml

Revision tag, roster, coders, concurrency, and the empty system prompt. Variants change only what differs, through extends:: config-v2 (the second prompt set), config-s3 (three answers per prompt, fewer calls at once), config-8 and config-8-v2 (eight models).

Prompts

prompts_v1.json, prompts_v2.json

Two sets of 200 English prompts in 10 categories, with the same design slot for slot. Some hide a trap or state a length or format limit. Everything is built and tuned on v1; v2 is the locked test set, its hash pinned by a test.

Models

Six profiled models

Astra, Fable, Opus, Argon, Flash, Muse. The eight-model test adds grok-4.7 and kimi-k3. Calls go through spectra/providers.py.

2. Code behavior

Two models outside the panel give each answer ten labels, each picked from a fixed list (yes or no for some, three or four choices for others). Agreement is Cohen’s kappa. Hand-check a sample before trusting these traits.

Coders: grok-4.7 and deepseek-v4-pro on the six-model runs; deepseek-v4-pro and mistral-large on the eight-model revisions, where grok-4.7 is in the panel and no model may label its own answers. Style traits do not need this step.

python -m spectra.tiebreak --coder <model>: a third coder from another family labels only the answers the two disagree on and writes tiebreak.json with the majority of three. codes.jsonl is not changed.

3. Measure

Style is computed from the text. Behavior comes from the codes when they exist. Nothing here is a quality score.

python -m spectra.analyze --previous <revision>
analysis.json and features.csv
trait profilessignature wordslimits metstyle mapauthor classifierrun cost and latency

The accent: for each everyday trait, how much of the variation between answers the model explains and how much the prompt; whether the categories rank the models alike (Kendall’s W); whether the order holds in the --previous revision; a family tree of the voices; and each model’s accent card.

The guessing game

A second operation on the same answers. Each model sees every reply with the author names removed and matches them to the roster. It is not told which model it is. Letters are shuffled separately for each guesser. Its own answer is left out of the headline scores.

Blind

The prompt, the answers, and the roster names. No measured profile.

--mode blind

Briefed

The same, plus habits from an analysis.json: length, formatting, hedging, signature words, limits. Cost and latency stay out.

--mode briefed --research <revision>

Held out

Prompts split in half by category. Each half is guessed with notes measured only on the other half, so the answer in front of the model did not write its own brief.

--mode heldout

Portraits

The brief is replaced by the portraits the models wrote of themselves, or of each other, in the self-knowledge probe.

--mode described --portraits self|peer

Assignment. The default asks for each model once, so naming one answer narrows the rest. --independent asks for a name per answer, with repeats allowed. --dry-run builds the messages and estimates cost without calling a model. Held-out notes are written under holdout/half-A and holdout/half-B.

Profile variants. --profile adds parts to the plain profile: portrait, pairs (the most confused pairs), examples (quoted openings and closings), category, or all. Each part is built from the same source as the profile, never from the answers being guessed, and each profile is scored as its own game. --guessers lets only some models guess, and --compare-profiles prints a guesser's accuracy with every profile against the plain one, without calls.

one call per guesser per prompt

Pre-registration, step by step

Every paid experiment after the first runs follows the same order. A deviation is appended to the registration; the registration itself is never edited.

  1. Write it. Hypotheses, metrics, prompt lists, exact messages and the analysis, in spectra/prereg/<date>-<name>.md.
  2. Price it. Dry runs build every message; --dry-run or voice budget gives the cost from measured prices.
  3. Approve the budget. No call is made before the cost estimate is approved.
  4. Register it. Commit and push the file together with its code before the first call. The commit is the timestamp.
  5. Collect. Run the registered commands; rerun to retry failures.
  6. Score. Run the registered scoring command, unchanged.
  7. Report. Write <name>-results.md: each test, its verdict, and every deviation with its reason.
  8. Check. The paper’s build compares each registration’s commit time with the first record it governs.

The paper and the brochure

spectra/article/make_assets.py writes every number, table and figure of the paper into spectra/article/generated/ from the run files; the text reads numbers only through those macros. The brochure’s newer cards quote the same macros.

Files for a revision live in data/spectra/<revision>/. The revision name matches a PeerRank revision, so the profile describes the same deployment.
