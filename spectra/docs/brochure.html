The accents of frontier LLMs

Spectraaccents models mishear

Ask six frontier models the same question and you hear six accents. Each is small in any one answer, steady across tasks, runs and new prompts, and larger in how each model reacts to particular prompts. The models mishear their own: they describe the stereotype of AI writing, can't imitate each other from a name, and can't hide. Measured, an accent becomes something you can use. It spreads to whoever reads the text, more to some readers than to others. When two more models joined the panel, the accent, the misheard descriptions and contagion held.

The idea

A different question about the same models

A ranking

Which model answers best?

Leaderboards and peer evaluations, such as PeerRank, score answers and order the models. The result is an order, not a description of how each model writes.

Spectra

How does each model write?

Six frontier models answer 200 everyday prompts with no system prompt and no web search. The result is a profile of habits for each model, with no ranking and no judge of quality.

Two models can be equally good and still suit different jobs. In run oct-23-26, gpt-6-astra answered in about words and gemini-4-argon in about , and that order held in every one of the 10 categories. A ranking hides that. A profile shows it.

What's new

Six ideas Spectra is built on

An accent, not a score

Each habit is split into what the prompt sets and what the model adds, then checked across 10 task categories, a second run, and 200 new prompts locked before collection. The model's part is small and steady. That is the accent.

Two ways of measuring

Thirteen style traits are computed straight from the text: length, formatting, hedging, em dashes, reading ease and more. Ten behaviors, such as answering first or flagging an error, are labeled by two coder models from outside the panel. Coders never see which model wrote the answer.

Traps inside ordinary prompts

of the 200 prompts hide one of five traps, and state a length or format limit. They read like normal requests, so a model shows its habit, not its test-taking.

Can a model hear itself?

Each model describes its own writing and the others', writes a portrait a reader must recognize it by, imitates the other five, and tries to hide its own voice. Every answer is checked against the measurements.

Does an accent spread?

A model answers after reading another model's earlier answers as notes, the way agents share memory. Nothing asks it to imitate. Spectra measures how far its answers drift toward the notes' author.

Pre-registered

Hypotheses, prompt lists, messages and code were committed before each experiment's first call, and deviations are logged next to them, including a confound found afterwards.

Architecture

Three inputs, one model layer, five steps

One module talks to the model APIs; every step reads and writes plain files under data/spectra/<revision>/.

Configspectra/config.yaml

Revision tag, the six models, the two coders, concurrency, timeouts, and an empty system prompt.

Promptsprompts/prompts_v1.json, prompts_v2.json

Two sets of 200 English prompts in 10 categories, built to the same design slot for slot. Everything is built and tuned on v1; v2 is the locked test set, its hash pinned by a test. Each prompt has an id, a category, its text, trap tags, and an optional limit.

Model accessspectra/providers.py

The one module that calls models. It reuses PeerRank's provider layer, so every model gets the same answering settings; a model outside it can go through LiteLLM.

How a run works

Five steps, followed through one prompt

Run from the repository root. Paid steps call models; local steps only read files. Figures are from run oct-23-26.

1

Collect answers

python -m spectra.run --revision oct-23-26
  • Every model answers every prompt once: 200 prompts × 6 models = calls, sent in random order.
  • The prompt is the only message. No system prompt and no web search, so this is how each model behaves through the plain API.
  • Answering settings: up to output tokens (gemini-4-argon , to leave room for thinking) and temperature 1.0 for all six. Three of them accept no other value; the other three are set to 1.0 so the panel matches.
  • Limits: a -second timeout, retries, and at most calls at once per provider.
  • Saved per answer in responses.jsonl: the text, latency, input and output tokens, and cost. Output tokens include hidden thinking. run_config.json records each model's exact settings.
  • Rerun to resume: answers already saved are skipped and only failed calls are retried.
2

Label behaviors

Paid · optional
python -m spectra.code_behaviors --revision oct-23-26
  • Two coder models read every answer: . Neither is in the profiled six, so no model labels its own writing, and they come from different families so their agreement can be measured.
  • What a coder sees: the label definitions, the prompt's trap tags, the user's prompt, and the answer. Never the author.
  • What it returns: one JSON object with ten labels, each picked from a fixed list. Fixed choices are easier to check than 1-to-10 scores.
  • Trap labels are conditional. "Premise" is only judged on prompts tagged FP, "error handling" only on ERR, and so on. Elsewhere the coder answers "not applicable".
  • Checked on the way in: any value not on the list is dropped; a reply with no JSON is saved as an error and retried on the next run. This run coded answers, ten labels each.
3

Measure

Local
python -m spectra.analyze --revision oct-23-26
  1. Load: keep the last successful answer for each model, prompt and sample.
  2. Measure the text of every answer, code blocks removed: words, formatting (headers, list items, bold, table rows), hedges, caveats, warm openers, closing questions or offers, exclamations and emoji, em dashes, stock phrases, reading ease, vocabulary range, self-reference. Prompts with a limit are checked for whether it was met.
  3. Turn labels into numbers: each label is 1 or 0 per coder, and the two coders are averaged, so a split counts as half. Trap traits use only prompts with their tag.
  4. Compare with the panel: average per prompt, then across prompts, with a 95% interval from 2,000 resamples of prompts. The effect size d is the distance from the six-model average in standard deviations. Each category is also checked on its own.
  5. Profile each model: its strongest departures, its closest neighbor, how often it met each kind of limit, and its latency, tokens and cost.
  6. Find signature words that a model uses more than the others (log-odds with an informative prior, z ≥ 2.5, at least 8 uses).
  7. Test distinctiveness: a classifier names the author from words and style, tested only on prompts it never trained on.
  8. Map style in two dimensions (principal components) and measure coder agreement (Cohen's kappa).

Output: features.csv, one row per answer, and analysis.json, which the report, the guessing game and this page all read.

4

Play the guessing game

python -m spectra.guess --revision oct-23-26 --mode heldout
  • One call per model per prompt: the model sees the six answers with author names removed, in a letter order shuffled for each guesser, and names the author of each. It is never told which model it is.
  • Scoring leaves a model's own answer out. Chance is 1 in 6. An ambiguous name such as "claude" counts as a miss.
  • Assignment: by default every model must be used once, so placing one answer narrows the rest. --independent allows repeated names; guessers used that in of calls, and scored that way against naming each model once.
  • Profile variants: --profile adds portraits, notes on the most confused pairs, quoted openings and closings, or notes for the prompt's category, each scored as its own game. --guessers lets one strong guesser try them cheaply.
  • --dry-run builds every message and estimates the cost without calling a model.

5

Build the report

Local
python -m spectra.report --revision oct-23-26

One self-contained report.html per run. It reads analysis.json and any guessing games already played, and does not rerun the analysis.

Related work

Where Spectra sits

Earlier work shows that models have voices, can be told apart, and do not report on themselves reliably. Spectra measures the accent, tests what models know about it, and measures how it spreads.

  • Do LLMs write like humans? (Reinhart et al., PNAS 2025) and Beyond "AI Language" (Rudnicka and Juzek, 2026). Models have consistent grammatical and idiolect-like signatures; Spectra splits each habit into what the model and the prompt contribute.
  • Self-Assessment Tests are Unreliable (Gupta et al., 2023) and Looking Inward (Binder et al., 2024). Self-reports shift with wording; fine-tuned models can predict their own behavior. Spectra checks untrained self-descriptions against measured writing, with every model describing every other as a control.
  • Do language models accommodate their users? (Blevins et al., EACL 2026). Models converge toward the style of a conversation; Spectra measures one model's accent moving into another's answers through notes.
  • Idiosyncrasies in Large Language Models (Sun et al., ICML 2025). A trained classifier names the source family with 97.1% accuracy; the signal sits in word choice.
  • VibeCheck (Dunlap et al., ICLR 2025). Judge-scored "vibes" separate two models at a time; Spectra profiles six at once without a judge.
  • Style, Not Self (Barkhordar and Thapa, 2026). Apparent self-recognition of code is mostly style and length; Spectra asks the same question of prose.
  • YapBench (Borisov et al., 2026). Verbosity across 76 assistant models; Spectra measures 23 traits together.
  • PeerRank (Margalit et al., 2026). Peer evaluation with self, identity and position bias measured; Spectra covers the style side it leaves open.
Limits

What these numbers do not say

  • Not a quality score. Spectra does not check whether an answer is correct. A long answer can be the right one.
  • Relative to this panel. Effect sizes compare the six models with each other. Adding or removing a model moves everyone, though the findings held when two were added.
  • Thin traps. Each trap kind rests on 5 to 11 prompts, enough for large differences and too few for fine ones.
  • Synthetic, English prompts. They are written to resemble everyday requests, in English only.
  • Plain API behavior. No system prompt. A product built on these models can change many of these habits.
  • Machines, not people. Recognition, imitation and hiding are scored by a classifier and one guesser; whether people hear the same accents is untested.
  • One imitation confound. The pre-registered imitation measure missed that any fresh answer drifts toward the other models; imitation is reported against the same model imitating itself, and the deviation is logged. Re-scoring against three answers per prompt fits regression to the mean, but the corrected comparison has not been run again with new imitations.
  • One exposure. Contagion was measured after reading five notes once; whether it accumulates over many exposures is the next test.
  • Rewrites keep content only approximately. Rewrites by another model kept slightly fewer of the original names and numbers than self-rewrites, a difference the crossed design cancels; the check found no sign of a rewriter carrying in its own, but it cannot see meaning, emphasis or recommendations.
  • Coder judgment. Behavior labels come from two models, not people. Agreement is reported per label, a third coder from another family settled the labels the two disagreed on, and answering first ranks the models the same under any of them; moral commentary is too rare to rank.
  • An open question.
